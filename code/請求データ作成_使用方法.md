# 請求データ作成の使用方法



勤務表解析 GUI（`main.py`）における、**請求データ作成**および関連ボタン（請求データ削除・請求ファイル更新）の現行仕様です。



## 概要



解析結果グリッドの各行から、請求用 Excel に書き込むための **更新用列** を自動作成します。実際の Excel 反映は別ボタン「請求ファイル更新」で行います。



| ボタン | 役割 |

|--------|------|

| **請求データ作成** | グリッドに「更新用合計勤務時間（10進）」「更新用交通費合計」を設定 |

| **請求データ削除** | **更新用合計勤務時間（10進）** と **更新用交通費合計** をクリア |

| **請求ファイル更新** | 最終判断「〇」の行を、選択した請求用 Excel に反映 |



## 前提条件



- グリッドに解析結果が表示されていること（新規解析または JSON 読込）。

- **請求ファイル更新** を行う場合は、画面上部の **請求用ファイル**（`.xlsx` / `.xlsm` 等）を参照で指定しておくこと。

- 解析実行そのものには、データフォルダと請求用ファイルの両方の選択が必要（請求データ作成ボタン単体では請求用ファイルは必須ではない）。



## 請求データ作成



### 操作手順



1. 必要に応じてグリッドで行を選択する（未選択の場合は **全行** が対象）。

2. **請求データ作成** をクリックする。

3. 確認ダイアログで OK を押す。



### 対象範囲



- **行を1件以上選択している場合**: 選択行のみ。

- **選択がない場合**: グリッドの全行。



対象行リストに対して `populate_billing_update_columns`（`kintai_core.py`）が実行されます。処理開始時に、対象行の更新用列はいったんクリアされます。



### 各行の更新用列（1行1値）



**社員番号が有効な各行**を独立に処理します。同一社員番号が複数行あっても **合算しません**。



社員番号は次の順で取得します。



1. 行データの `employee_no` / 「社員番号（ファイル名より）」

2. 対象ファイル名から抽出した社員番号（7桁数字、または `BP` + 5桁）



社員番号が有効形式でない行はスキップされます（`^\d{7}$` または `^BP\d{5}$`）。



| 設定する列 | 値の元 |

|------------|--------|

| 更新用合計勤務時間（10進） | その行の「合計勤務時間（10進）」列（`total_hours_decimal`） |

| 更新用交通費合計 | その行の「交通費合計（読取）」列（`transport_expense_raw`） |



**合計勤務時間も交通費も両方空**の場合は、その行はスキップされ、更新用列は空のままです。



### 完了時の表示



- ステータス欄: `請求データ作成完了（{対象}）: {N} 行に更新用列を設定しました`

- メッセージボックス: 設定した行数



「行数」は、上記ルールで更新用値が1回以上設定された行の件数です。



### ボタン有効条件



- 解析処理中（`_busy`）は無効。

- グリッドに1行以上あるとき有効。



## 請求データ削除



### 操作手順



1. 対象行を選択するか、未選択で全行対象とする（請求データ作成と同じ範囲ルール）。

2. **請求データ削除** をクリックし、確認する。



### 削除される内容



- **更新用合計勤務時間（10進）** と **更新用交通費合計** をクリア（`clear_billing_update_hours_column` → 内部で両列をクリア）。



## 請求ファイル更新（請求データ作成後の流れ）



請求データ作成だけでは Excel は変更されません。反映には **請求ファイル更新** を使います。



### 操作手順



1. 必要に応じてグリッドで行を選択する（未選択の場合は **全行** が走査対象）。

2. **請求ファイル更新** をクリックし、確認する。



### 走査範囲（グリッド）



請求データ作成・請求データ削除と同じです。



- **行を1件以上選択している場合**: 選択行のみ。

- **選択がない場合**: グリッドの全行。



上記の範囲のうち、次を **すべて**満たす行だけ Excel に反映します。



| 条件 | 内容 |

|------|------|

| 最終判断 | 「〇」 |

| 更新用合計勤務時間（10進） | 値があり、旧仕様の合算済マーカー **ではない**（レガシー互換） |



条件を満たさなかった行や、走査範囲外の行は **請求用ファイル更新** 結果列は更新しません。



旧仕様で残っている `No.XXのレコードに合算済` は更新対象外です。**請求データ作成** を再実行すると通常の値に置き換わります。



### 請求用 Excel の更新先



- シート名: **エンジニアTS一覧**

- 行の特定: 対象ファイル名から **取引先名（末尾の「様」を除去）** と氏名を解析し、シートの **D列（取引先名）・E列（氏名）** と照合した **行のみ** H列・O列を更新する（A列社員番号だけでは全行更新しない）。

- 同一社員番号・同一取引先で複数行ある場合は、**ファイル名の氏名と E 列が一致する行**のみ更新する。



| Excel 列 | 内容 | グリッドの元 |

|----------|------|----------------|

| H列 | 通常請求時間 | 更新用合計勤務時間（10進） |

| O列 | 旅費交通費請求金額 | 更新用交通費合計 |



交通費の扱い（O列）:

- **（データなし）** および更新用列が空欄 → Excel のセルを **空** にする（0円にはしない）。
- **（なし）**・**不明** など → **0円** として書き込む。

**請求データ作成** 実行時、読取列が（データなし）の場合は更新用交通費合計列も空欄になります。



### 既存値がある場合の上書き確認



対象 Excel 行の **通常請求時間（H）・旅費交通費（O）が両方空** のときは、確認なしで両方に新値を書き込みます。

**どちらか一方または両方**に既存値（セルが空でない。数値 `0` も既存あり）があるときは、上書き確認ダイアログを表示します。

| 表示 | 内容 |
|------|------|
| 通常請求時間（現在） / （更新後） | Excel の現値と、グリッドから書き込む値（空は `（空）`） |
| 旅費交通費（現在） / （更新後） | 同上。更新後が空セルにする場合は **（空）** と表示 |
| 勤務時間を上書き / 交通費を上書き | 列ごとのチェック。OFF の列は Excel を変更しない（既存の交通費を空にする場合も、このチェックで実行可否を選べます） |

キャンセルした場合は Excel は保存されません。両方のチェックを OFF にして実行した行は **スキップ** となります。



### 同一社員番号の複数グリッド行について（運用注意）



グリッド上では行ごとに別の更新用値が入ります。複数のグリッド行が **同じ D/E 行**（同じ取引先・氏名）に対して更新される場合、請求ファイル更新はグリッド行を順に処理するため **後から処理した行の値で上書き**されます。同一社員で複数ファイルがある場合は、**反映したい行だけを選択して請求ファイル更新**する、または **反映したい1行だけ「〇」** にするなどの運用を推奨します。



### 請求用ファイル更新の結果列



グリッドの **請求用ファイル更新** 列に次のいずれかが入ります。



| 表示 | 意味 |

|------|------|

| 〇 | シートへの書き込み成功（1列以上を更新） |

| スキップ | 上書き確認で勤務時間・交通費の両方のチェックが OFF |

| ✖ | 書き込み失敗、旧合算済マーカー行、勤務時間不正、交通費不正など |

| （対象レコードなし） | ファイル名と請求シートの D/E 列照合で一致行がない |



## 推奨ワークフロー



```mermaid

flowchart LR

  analyze[新規解析またはJSON読込]

  judge[最終判断を確認・修正]

  create[請求データ作成]

  update[請求ファイル更新]

  analyze --> judge --> create --> update

```



1. データフォルダ・請求用ファイルを指定し、解析を実行する。

2. 会社名・氏名・勤務時間・種別照合などを確認し、**最終判断** を必要に応じて編集する。

3. **請求データ作成** で各行の更新用列を作る。

4. 請求用ファイルを指定し、**請求ファイル更新** で Excel に反映する。

## 補足



- グリッドの JSON 保存・読込時、請求用ファイルのパスは `billing_file_path`（または `billing_file`）として保存されます。
