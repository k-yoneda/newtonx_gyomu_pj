# 請求データ作成の使用方法

勤務表解析 GUI（`main.py`）における、**請求データ作成**および関連ボタン（請求データ削除・請求ファイル更新）の現行仕様です。

## 概要

解析結果グリッドの各行から、請求用 Excel に書き込むための **更新用列** を自動作成します。実際の Excel 反映は別ボタン「請求ファイル更新」で行います。

| ボタン | 役割 |
|--------|------|
| **請求データ作成** | グリッドに「更新用合計勤務時間（10進）」「更新用交通費合計」を設定 |
| **請求データ削除** | **更新用合計勤務時間（10進）** と **更新用交通費合計** をクリア |
| **請求ファイル更新** | 最終判断「〇」の行を、選択した請求用 Excel に反映 |

## 前提条件

- グリッドに解析結果が表示されていること（新規解析または JSON 読込）。
- **請求ファイル更新** を行う場合は、画面上部の **請求用ファイル**（`.xlsx` / `.xlsm` 等）を参照で指定しておくこと。
- 解析実行そのものには、データフォルダと請求用ファイルの両方の選択が必要（請求データ作成ボタン単体では請求用ファイルは必須ではない）。

## 請求データ作成

### 操作手順

1. 必要に応じてグリッドで行を選択する（未選択の場合は **全行** が対象）。
2. **請求データ作成** をクリックする。
3. 確認ダイアログで OK を押す。

### 対象範囲

- **行を1件以上選択している場合**: 選択行のみ。
- **選択がない場合**: グリッドの全行。

対象行リストに対して `populate_billing_update_columns`（`kintai_core.py`）が実行されます。処理開始時に、対象行の更新用列はいったんクリアされます。

### グループ化のキー

**社員番号**でグループ化します。社員番号は次の順で取得します。

1. 行データの `employee_no` / 「社員番号（ファイル名より）」
2. 対象ファイル名から抽出した社員番号（7桁数字、または `BP` + 5桁）

社員番号が有効形式でない行はグループ化の対象外です（`^\d{7}$` または `^BP\d{5}$`）。

### 社員番号が1件だけのグループ

| 設定する列 | 値の元 |
|------------|--------|
| 更新用合計勤務時間（10進） | 「合計勤務時間（10進）」列（`total_hours_decimal`） |
| 更新用交通費合計 | 「交通費合計（読取）」列（`transport_expense_raw`） |

**合計勤務時間も交通費も両方空**の場合は、その社員番号グループはスキップされ、更新用列は空のままです。

### 同一社員番号が複数行あるグループ

1. **No** が最小の行（グリッド上で先頭の行）を代表行とする。
2. 代表行に以下を設定する。
   - **更新用合計勤務時間（10進）**: 各行的「合計勤務時間（読取）」を時間数に変換して **合算**（いずれか1行でも変換できない場合は勤務時間側は空）。
   - **更新用交通費合計**: 各行的「交通費合計（読取）」を金額に変換して **合算**（いずれか1行でも変換できない場合は交通費側は空）。
3. 代表行以外の行には、次のマーカーを **勤務時間・交通費の両列** に設定する。

   `No.{代表行のNo}のレコードに合算済`

   例: 代表が No.3 なら `No.3のレコードに合算済`

4. 合算後の勤務時間・交通費が **両方空** の場合は、そのグループはスキップされます。

### 完了時の表示

- ステータス欄: `請求データ作成完了（{対象}）: {N} グループに更新用列を設定しました`
- メッセージボックス: 設定したグループ数

「グループ数」は、上記ルールで更新用値が1回以上設定された社員番号グループの件数です。

### ボタン有効条件

- 解析処理中（`_busy`）は無効。
- グリッドに1行以上あるとき有効。

## 請求データ削除

### 操作手順

1. 対象行を選択するか、未選択で全行対象とする（請求データ作成と同じ範囲ルール）。
2. **請求データ削除** をクリックし、確認する。

### 削除される内容

- **更新用合計勤務時間（10進）** と **更新用交通費合計** をクリア（`clear_billing_update_hours_column` → 内部で両列をクリア）。

合算済マーカー（`No.XXのレコードに合算済`）が入っている行も、両方の更新用列が空になります。

## 請求ファイル更新（請求データ作成後の流れ）

請求データ作成だけでは Excel は変更されません。反映には **請求ファイル更新** を使います。

### 更新対象行（グリッド）

次を **すべて**満たす行のみ（**選択行ではなく常に全行を走査**）。

| 条件 | 内容 |
|------|------|
| 最終判断 | 「〇」 |
| 更新用合計勤務時間（10進） | 値があり、合算済マーカー **ではない** |

### 請求用 Excel の更新先

- シート名: **エンジニアTS一覧**
- 行の特定: 対象ファイル名から会社名・氏名を解析し、シートの **D列（取引先名）・E列（氏名）** と照合。一致した行の **A列** の社員番号を使用。
- 同一社員番号がシート内に複数行ある場合は、該当する **すべての行** を同じ値で更新。

| Excel 列 | 内容 | グリッドの元 |
|----------|------|----------------|
| H列 | 通常請求時間 | 更新用合計勤務時間（10進） |
| O列 | 旅費交通費請求金額 | 更新用交通費合計 |

交通費は空欄・（なし）等は **0円** として扱われます。

### 請求用ファイル更新の結果列

グリッドの **請求用ファイル更新** 列に次のいずれかが入ります。

| 表示 | 意味 |
|------|------|
| 〇 | シートへの書き込み成功 |
| ✖ | 書き込み失敗、合算済行、勤務時間不正、交通費不正など |
| （対象レコードなし） | ファイル名と請求シートの会社・氏名照合で社員番号が取れない、または A列に該当社員番号の行がない |

## 推奨ワークフロー

```mermaid
flowchart LR
  analyze[新規解析またはJSON読込]
  judge[最終判断を確認・修正]
  create[請求データ作成]
  update[請求ファイル更新]
  analyze --> judge --> create --> update
```

1. データフォルダ・請求用ファイルを指定し、解析を実行する。
2. 会社名・氏名・勤務時間・種別照合などを確認し、**最終判断** を必要に応じて編集する。
3. **請求データ作成** で更新用列を作る（同一社員の複数ファイルは自動合算）。
4. 請求用ファイルを指定し、**請求ファイル更新** で Excel に反映する。

## 補足

- グリッドの JSON 保存・読込時、請求用ファイルのパスは `billing_file_path`（または `billing_file`）として保存されます。
- 合算済マーカーが入った行は **請求ファイル更新の対象外** です。代表行のみ Excel に書き込まれます。
